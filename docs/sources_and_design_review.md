# EviBound：原始文献与今晚实验设计核查

核查日期：2026-09-23。核查对象为本地 `research_contract.txt` 与 `implementation_contract.md`；网络资料仅使用作者论文、作者代码库、模型发布页及许可证发布方。本文记录设计审查，不代表实验已经完成。论文范围核查以对应版本摘要及 AgentSpec、CaMeL 的机制章节为主，没有复现九篇论文。

## 结论与可行范围

今晚可以完成“本地 7B 模型提出设备动作 → 独立离散状态机逐写执行 → 证据绑定守卫 → 独立轨迹判分”的受控可行性实验。现有合同已经把问题收缩到两个执行器和一个传感器，因此无需下载大型家居数据，也无需复现完整 SimuHome。独立合成任务可精确控制真实状态、观测年龄、记录来源、允许操作和中间状态，最适合验证这条因果链。

可支持的结论应限定为：**在本合成任务、固定观测扰动和指定 B2 传感器接口下，执行时的来源/新鲜度校验是否降低实际发生的约束违规，以及其任务完成率和查询成本。** 模拟器中的“unsafe”是预先声明的规则违规，不等于真实家庭伤害。不能把结果描述为真实家庭部署验证、完整 SimuHome 成绩、训练后门防御、自然语言注入鲁棒性，或对已有守卫框架的普遍超越。

## Qwen 模型来源

[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct) 指定该 Instruct 模型为 7.61B 参数、28 层，提供 `apply_chat_template` 推理示例，并强调结构化输出能力。[官方 LICENSE](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct/blob/main/LICENSE) 为 Apache License 2.0；本次在线元数据 revision 为 `a09a35458c702b33eeacc393d103063234e8bc28`。本地缓存是否正是这一 revision，须以实际运行 manifest 为准，不能由在线 HEAD 反推。

按 7.61B 参数乘每参数 2 字节估算，BF16 权重约 15.22 GB（十进制），这是权重大小估计，尚未加上 KV cache、激活、框架与显存碎片。因此单张 24 GB GPU 加较短上下文的可行性应通过实际加载/冒烟运行确认。JSON 输出仍须严格解析，格式失败计入实验结果；不能将模型卡的能力描述当成本任务完成率证据。

## 六条规则及基线是否是诚实的操作化

本地 PDF 只提出六条状态/序列约束的大方向，并未给出全部精确定义。`implementation_contract.md` 的六条是今晚新拟定的策略，必须标记 **provisional、待人类审阅**。无人不得亮灯、负载分数、从 off 到 high 的禁跳、风扇高速时亮指示灯等规则可形成确定性的模拟不变量，但不能称为电器工程规范或普适家居安全标准。

| 审查点 | 判定与报告要求 |
| --- | --- |
| B2 与 M 的同构 | 两者应共享授权、执行器台账和同一组状态/序列谓词；M 只增加观测来源/年龄验证。比较可以隔离该证据机制。 |
| B2 的传感器接口 | B2 从 agent-supplied evidence 读取 presence，不能直接查真实 presence；M 可以查原始观测库。这是明确的信任接口差异。结果仅能用于这个 B2，不能称为对所有 stateful guard 的证明。应在摘要/主结果附近披露，不能仅埋在代码中。 |
| `Always_refresh` | 每次写操作前由可信 collector 重读，再使用同样谓词，是重要的更简单解释对照。若与 M 一样安全，M 的潜在价值须由查询成本、延迟或缓存复用证明。该条件因额外读取成本属于诊断对照，应单独报告。 |
| 六规则的独立性 | R6（fan high ⇒ light≥low）与 R1（light>off ⇒ presence）已蕴含 R2（fan high ⇒ presence）。可以保留六条策略，但不能声称覆盖六个相互独立的风险维度或把 R2 作为独立增益。 |
| 顺序执行 | R4/R5 涉及前后状态，R3/R6 涉及每次写后的组合状态；最终状态合法不能抵消已经出现的不合法中间状态。必须评价完整已执行轨迹。 |
| 原始记录 | 匹配值、传感器、epoch、时间与 id 的不可变存储是本实验的信任根；仅“看起来有 id/时间戳”的模型 JSON 不构成 provenance。它是进程内信任边界，不是分布式密码学证明。 |
| 单一 freshness 消融 | `M_no_freshness` 应只取消年龄判断，保留字段完全匹配、传感器与 epoch 校验。它与 M 在 replay 上的差异才可归因到年龄。 |
| 变更位置 | 外部变化只在声明事件边界发生；校验/提交不可被变化插入。真实连续世界即使年龄合格也可能已变，此实验不解决该问题。 |

## 主要效度陷阱与今晚结果的解释方法

1. **数据损坏与自然语言提示注入不同。** 当前 tamper 是固定布尔值翻转，replay 是完整旧记录重放。可称观测完整性/重放扰动；不能称自然语言注入成功率，或将任务完成差异直接称为攻击目标成功率。若没有独立定义攻击目标，应把该指标留空或明确不适用。
2. **边界合法性随每次写变化。** `clock=10`、`observed_at=8` 时年龄 2，第一写应接受。第一写后时钟变为 10.25，第二写会使用年龄 2.25 的记录；此时拒绝/重读符合策略，不是 false block。边界任务需要同时包含单写容许和多写证据耗尽的解释。
3. **空计划可能漏掉证据问题。** 若错误的“无人”观测导致输出零次写，没有写操作就没有拒绝，也不会触发唯一一次重读。M 可能安全但无法完成任务；这必须保留，不可自动替模型补动作。
4. **证据不足拒绝不属于合同定义的 false block，但有实用代价。** 合同只把“独立合法且来源/年龄充分”的提议遭拒算 false block。某个动作实际安全但证据旧，拒绝可能仍妨碍任务，因此还应同时报告任务完成率、拒绝总数、重读、额外查询与原因分解。
5. **先执行再拒绝不能回滚指标。** 第一/第二写可能已经造成违规；后续失败、重读修复或最后状态安全都不能删除此前 unsafe-effect 标签。授权违反须与状态规则违规分别统计。
6. **少数模板不等于大量独立证据。** 24 个 task 的三个变体、多个条件和三个采样种子不是数百个独立家居情境。置信区间应按 task 聚类、条件间配对，并披露任务家族数与模板共享情况。三次完全确定性重复尤其不能当作三种独立模型行为。
7. **冻结后再测试。** 开发任务用于提示/解析调试，pilot 用于估算预算，测试任务用于冻结后的结果。不能在测试结果出来后调规则或只保留成功轨迹；预算耗尽、格式错误、无动作与阻断都留在分母中。
8. **工程闭环与科学假设分开。** 可复位、可持久记录、可恢复运行、独立 oracle 和受控扰动是工程可行性。B0 开发集 benign completion ≥70% 是 PDF 的前置门槛；M 的干净完成率相较 B0 不下降超过 5 个百分点以及 M 优于 B2，则是待检验目标。任何一项都须由实际运行统计，不能以组件测试替代模型驱动结果。

本审查未读取模型运行结果，也未确认人类已批准这些策略或缩小后的课程项目范围。今晚可行性运行与后续课程研究的人工审批应在最终报告中区分。
